**3. 推薦 A，但必須把以下契約一起定下來**

1. **偵測變更先停止，不能先換資料再試舊操作。**  
   `raw !== lastRaw` 回 `STATE_CHANGED`，並鎖定本頁為失效狀態；本次不執行 reducer、不寫入、不沖刷 pending。保留舊快照到頁面退出，避免舊 DOM 突然讀到 `session:null`。這不是一般 `SAVE_FAILED`，不能只給「再存一次」。

2. **所有入口共用同一失效流程。**  
   包含 `dispatch／flushPending／retry`、`visibilitychange`、`storage`，以及既有同步的 `onReplaced`。當筆 handler 必須停止，不能排了重載後繼續 `feedback()` 或 `drawTasks()`。失效期間停動畫、禁止再操作，每個頁面只排一次重載。

3. **事件只作通知，仍重讀當下存檔。**  
   只處理本站 key，以及 `clear()` 的 `key === null`；排除其他站 key、probe、`sessionStorage`。自己的成功寫入更新 `lastRaw`。同頁修改不會收到自己的 `storage` 事件，事件也可能延後，因此操作前的比對不可省。[WHATWG Web Storage 規範](https://html.spec.whatwg.org/multipage/webstorage.html#the-storage-interface)

4. **待存操作不能跨換代自動重播。**  
   沒有 pending：自動重載，顯示「紀錄已更新，請從這裡繼續」。  
   有 pending：停止重試，顯示「紀錄已在別處更新，這一步需要重做」，提供「載入最新紀錄」；確認後取消舊 pending，再重載。一般寫入失敗且存檔沒變，維持原 ID 重試成功一次的既有行為。

   **原 M6「刪除後舊操作仍須重試成功」要改成「有明確恢復出口，重载後新操作能成功」**，否則仍在要求失去前提的操作繼續執行。

5. **自然站必須防止重載復活舊版資料。**  
   [已驗證] 本輪新增反例：保留 `g5sci.v1`、刪除 `g5sci.v3`、重新建立 store，`load()` 會搬入舊紀錄。[搬移入口](/Users/william/Documents/g5-sci-review/src/core.js:592)  
   外部失效引發的重載，必須帶「新版不存在時不自動搬入舊版」的模式，直到新存檔成功前都保留；不能用無條件寫空白來避免搬移，否則可能蓋掉別頁剛寫的新紀錄。

推薦 A 的理由是：目前畫面狀態分散在多個全域變數與閉包；整頁重載可以一起丟棄它們，驗收面比逐一恢復小。
